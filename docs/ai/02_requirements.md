# AI質問機能 要件定義書 (`02_requirements.md`)

## 1. 文書情報・目的

- **関連文書**: `01_request.md`（AI質問機能 追加要望書）
- **目的**: 既存の Express / TypeScript 製 Web アプリケーションに「AI質問機能」を追加するにあたり、機能要件・入力制約・画面仕様・非機能要件・受入基準を確定する。
- **対象システム**: 既存 Express / TypeScript アプリケーション（`src/apps/todo/` 等と同列のレイヤー構成）

---

## 2. システム概要・採用技術方針

### 2.1. 利用AIサービス・SDK選定（標準採用案）
- **AIサービス**: Google Gemini API（Gemini Developer API）
- **公式SDK**: `@google/genai`（旧 `@google/generative-ai` は非推奨のため、現行公式の `@google/genai` を採用）
- **使用モデル**: 環境変数 `AI_MODEL` で切り替え可能とし、デフォルト値はコストと応答速度のバランスに優れた Flash 系最新安定版（例: `gemini-3.8-flash` / `gemini-2.5-flash` 等、環境変数で上書き可能）を設定する。

### 2.2. 画面配置・提供形態
- 要望書のスコープ案に基づき、独立した専用画面（`GET /ai`）および非同期APIエンドポイント（`POST /ai/ask`）として提供する。
- 将来的に TOP 画面や TODO 画面から遷移・連携しやすいよう、共通ヘッダーやナビゲーションからアクセス可能な URL 設計とする。

---

## 3. 機能要件

### 3.1. 画面表示機能（UI）
1. **初期表示 (`GET /ai`)**
   - ページタイトルおよび機能説明を表示する。
   - 質問入力用のテキストエリア（複数行入力対応）を表示する。
   - 現在の入力文字数カウンター（例: `0 / 2000 文字`）を表示する。
   - 「質問を送信する」ボタンおよび入力内容をクリアする「クリア」ボタンを配置する。
   - AIからの回答を表示する結果表示エリア（初期状態ではプレースホルダーまたは非表示）を配置する。
   - 既存画面（TODO一覧等）へ戻るためのナビゲーションリンクを配置する。

2. **送信中（ローディング）状態の制御**
   - 質問送信開始からレスポンス受信完了まで、送信ボタンを非活性（`disabled`）にし、二重送信を防止する。
   - 処理中であることが視覚的に分かるローディングインジケーター（「AIが回答を生成しています...」等）を表示する。

3. **回答表示機能**
   - サーバーから正常に回答を受信した場合、回答表示エリアに AI の回答テキストを描画する。
   - 改行や段落が読みやすく表示されるよう整形する（セキュリティ上、生HTMLの直接挿入は避け、適切なエスケープ処理または安全なレンダリングを行う）。
   - 回答結果をワンクリックでクリップボードにコピーできる「回答をコピー」ボタンを提供する（任意・UX向上施策）。

### 3.2. 質問送信・AI応答生成機能（API）
1. **質問受付 (`POST /ai/ask`)**
   - フロントエンドから JSON 形式（`{ "question": "質問内容" }`）でリクエストを受け付ける。
2. **入力バリデーション**
   - リクエストボディの存在チェックおよび型チェック（文字列であること）。
   - 前後の空白除去（`trim()`）後の必須チェック（空文字・空白のみの送信は不可）。
   - 最大文字数チェック（上限: **2,000文字**）。
3. **Gemini API 連携**
   - サーバーサイド（`aiService.ts`）にて `@google/genai` SDK を初期化し、システムプロンプト（日本語で簡潔かつ丁寧に回答する旨の指示）とユーザーの質問を送信して回答テキストを取得する。
   - 本フェーズでは**1問1答形式（ステートレス）**とし、サーバー側での会話履歴永続化（DB保存）はスコープ外とする。
4. **レスポンス返却**
   - 成功時は HTTP ステータス `200 OK` とともに JSON 形式（`{ "answer": "生成された回答", "model": "使用モデル名" }`）を返却する。

### 3.3. エラーハンドリング機能
1. **バリデーションエラー（クライアント起因: `400 Bad Request`）**
   - 質問が未入力、または 2,000 文字を超過している場合、API 呼び出しを行わずに `400` エラーと具体的なエラーメッセージを返却し、画面上に赤字等で表示する。
2. **認証・設定不備エラー（サーバー設定起因: `500 Internal Server Error`）**
   - 環境変数 `AI_API_KEY` が未設定または無効な場合、サーバー側でログを出力した上で、クライアントには内部詳細を露出しない安全なエラーメッセージを返却する。
3. **外部API通信エラー・レート制限・タイムアウト（`502 Bad Gateway` / `503 Service Unavailable` / `504 Gateway Timeout`）**
   - Gemini API 側でのレート制限（429）、サーバーエラー（5xx）、ネットワーク障害、または規定時間（例: 30秒）内のタイムアウトが発生した場合、例外を捕捉しユーザーに再試行を促すメッセージを表示する。
4. **安全性フィルタ（Safety Block）による応答拒否**
   - 公序良俗に反する質問等により Gemini API が回答生成をブロックした場合、クラッシュさせず「回答を生成できませんでした。質問内容を変えて再度お試しください。」等のメッセージを返却する。

## 4. 入力制約・データ仕様一覧

| 項目 | 仕様・制約 | 備考 |
| :--- | :--- | :--- |
| **質問テキスト (`question`)** | 必須 / 文字列 / `1`〜`2,000` 文字（前後空白トリム後） | 日本語・英語・記号・改行を含む一般的なテキスト |
| **会話履歴保持** | なし（1リクエスト完結型） | 将来拡張でセッション/DB履歴追加が可能な構成にする |
| **出力形式** | テキスト（改行保持） | フロントエンド側で XSS 対策を施して表示 |
| **API タイムアウト** | 30秒（目安） | 長時間ハングアップによるリソース枯渇を防止 |

## 5. 非機能要件

### 5.1. アーキテクチャ・保守性
- 既存の `src/apps/todo/` の責務分離（Router / Controller / Service）を厳密に踏襲する。
  - `aiRouter.ts`: ルーティング定義のみを担い、ビジネスロジックを持たない。
  - `aiController.ts`: HTTPリクエストのパース、バリデーション、HTTPステータスコードとJSON/HTMLレスポンスの制御を担う。
  - `aiService.ts`: `@google/genai` を用いた外部AI通信処理のみを担い、Express の `req`/`res` に依存しない純粋な TypeScript クラス/関数として実装する。

### 5.2. セキュリティ
- **APIキー保護**: APIキーは環境変数（`AI_API_KEY`、フォールバックとして `GEMINI_API_KEY` も許容可）からのみ読み込み、フロントエンドのJS/EJSやGit管理下のコードに絶対に含めない。
- **XSS（クロスサイトスクリプティング）対策**: AIが生成した回答（特にコードブロックや記号を含む回答）を画面に描画する際、`innerHTML` による無防備な挿入を禁止し、`textContent` を用いるか、Markdown変換を行う場合は必ずサニタイズ処理を実施する。
- **ログ出力の配慮**: エラーログには原因調査に必要なステータスコードやエラー概要を記録するが、APIキー等の機密情報はマスクまたは出力対象外とする。

### 5.3. 既存機能への非干渉（リグレッション防止）
- 既存の TODO アプリ機能（`/todo` 等）、データベース接続、既存の 404 ハンドラー、グローバルエラーハンドラーの挙動を変更・破壊しないこと。
- `index.ts` への組み込みは `app.use('/ai', aiRouter)` のマウント追加のみに留めること。

## 7. 受入基準（完了定義 / Definition of Done）

本機能は以下の条件をすべて満たした時点で要件達成とする。

1. `GET /ai` にアクセスした際、AI質問画面が正常に表示され、既存画面のレイアウトやCSSに影響を与えていないこと。
2. 正常な質問文を入力して送信すると、ローディング表示後に Gemini からの回答が画面に表示されること。
3. 空文字、スペースのみ、または 2,001 文字以上の入力で送信した場合、API通信を行わずに適切なバリデーションエラーメッセージが表示されること。
4. APIキー未設定やネットワーク遮断などの異常系において、サーバーがクラッシュせず、ユーザー向けのエラーメッセージが返却されること。
5. 既存の TODO アプリの CRUD 操作および 404 ページが従来通り正常に動作すること。
